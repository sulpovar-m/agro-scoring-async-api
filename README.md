## Запуск

Python 3.12 или новее. Из корня проекта:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Swagger UI: http://127.0.0.1:8000/docs

OpenAPI: http://127.0.0.1:8000/openapi.json

SQLite `agro_scoring.db` создаётся при первом запуске. Дополнительные серверы,
ключи API и ручное создание таблиц не нужны. Запускать одним worker: очередь
находится в памяти процесса. Сохранённые прогнозы переживают перезапуск.
Для Vireonix требуется доступ в интернет; его доступность зависит от провайдера.

## API

Все успешные ответы имеют код 200. Каждый HTTP-ответ содержит `X-Request-ID`
и `X-Process-Time` (секунды). Переданный `X-Request-ID` сохраняется, иначе
создаётся UUID. Ошибки содержат `detail` и `request_id`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Состояние процесса API |
| GET | `/model-info` | Метаданные модели |
| POST | `/predict` | Прогноз и запись в SQLite |
| POST | `/batch-predict` | Пакет от 1 до 8 хозяйств, одна транзакция |
| POST | `/predict-queued` | Один объект через dynamic batching |
| GET | `/queue-status` | Размер очереди и настройки batching |
| GET | `/predictions` | История; limit 1–100, необязательный risk_level |
| GET | `/predictions/by-weekday` | weekday, page ≥ 1, per_page 1–100 |
| GET | `/predictions/{request_id}` | Одна запись; 404 при отсутствии, 409 при нескольких |
| GET | `/requests/{request_id}/predictions` | Все записи одного запроса |
| POST | `/llm/chat` | Текстовый запрос к Vireonix |
| POST | `/predict-with-llm` | Скоринг и текстовое объяснение LLM |

Статический маршрут `by-weekday` объявлен раньше маршрута с идентификатором.
Дни недели: monday, tuesday, wednesday, thursday, friday, saturday, sunday.
Даты хранятся в UTC; пагинация применяет SQL COUNT, LIMIT и OFFSET.
Пустая страница возвращает 200 с пустым `data` и метаданными.

Пример запроса (Windows: используйте `curl.exe`, либо вставьте JSON в Swagger):

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -H 'X-Request-ID: demo-single-01' \
  --data-binary @examples/farm.json
```

В Swagger параметр `x-request-id` доступен у каждого маршрута.
Регионы: Krasnodar, Rostov, Stavropol. Для примера оценка равна 0.5, категория medium.
Все поля хозяйства обязательны. Как и в работе №1, площадь и культура
валидируются, но не участвуют в формуле. Модель основана на правилах,
её результат не является калиброванной вероятностью дефолта.

## Очередь, таймауты и ошибки

Максимальный пакет — 8, окно накопления — 50 мс, очередь — 100 ожидающих запросов.
Worker передаёт пакет в модель одним вызовом и сохраняет одной транзакцией.
Результаты возвращаются через индивидуальные Future. Полная очередь даёт 429.

`Settings.inference_timeout_seconds = 2.0` ограничивает именно вызов модели,
а не полное время ожидания в очереди и не операцию БД. Для проверки 504
тест временно задаёт 0.001 секунды. Дополнительных служебных HTTP-маршрутов нет.

Коды: 400 — бизнес-правило, 404 — нет результата, 409 — несколько результатов,
422 — Pydantic, 429 — очередь, 500 — внутренняя ошибка,
502 — HTTP/формат ответа LLM, 503 — недоступны модель, БД, worker или провайдер,
504 — таймаут модели или LLM. /health проверяет процесс, а не внешние зависимости.

## LLM

По умолчанию используется `https://vireonix.ai/v1`, модель `auto`, таймаут 60 секунд.
Авторизация отсутствует по ТЗ. Подключение — общий `httpx.AsyncClient` в lifespan.
LLM получает в комбинированном маршруте только учебные `risk_score` и `risk_level`.
Она не определяет числовой скоринг и не изменяет сохранённый прогноз.
Скоринг записывается до обращения к LLM: при сбое объяснения прогноз остаётся
в истории, а комбинированный запрос получает ошибку внешней зависимости.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Результат: 22 passed. Тесты используют временные SQLite-файлы и
`httpx.MockTransport`, не требуют интернета и не меняют рабочую БД.
Проверены перезапуск, пакетная транзакция, соответствие Future результатам,
пагинация, переполнение очереди, 0.001-секундный таймаут и ошибки провайдера.

При подготовке также выполнены настоящие HTTP-вызовы Vireonix: оба LLM-маршрута
вернули 200. В отчёте приведены отдельные результаты этих вызовов.
Скриншоты Swagger LLM-маршрутов сняты с явно обозначенным локальным тестовым
транспортом (`returned_model: test-provider`); приложение по умолчанию использует
реальный endpoint. Все значения хозяйств в примерах вымышлены.
